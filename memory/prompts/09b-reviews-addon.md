# 09b — Дополнение к 09: отзывы (ссылки для всех проектов, открытая форма, авто-просьба, импорт)

Выполнять вместе с 09 (в той же ветке trust-09) или сразу после. Правила те же: без стоп-точек, деплой сам после зелёных проверок,
бэкап и откат. Выдуманных отзывов не создавать ни в каком виде (38-ФЗ, UWG) — только механика.

## Как сейчас (для контекста)
- Отзыв приходит только по личной ссылке `/{lang}/review/<token>` (токены — `scripts/review-tokens.json` на russh, сейчас 2: VL и MP).
- `POST /api/review` → `scripts/data/reviews.json` (РФ-сервер), status `pending`, `verified: true` при токене → Telegram «⭐ Новый отзыв на модерации».
- Модерация — админка платформы → «Отзывы» (approve/reject/edit/delete). Блок `Reviews` берёт снимок сборки + `/api/reviews` в рантайме.

## 1. Ссылки для всех проектов
- Токены для всех 11 проектов из `src/data/portfolio.json` (16+ случайных символов, `crypto.randomBytes`), существующие 2 НЕ менять.
- Админка «Отзывы» → таблица «Ссылки для клиентов»: проект, ссылка ru/de/en, кнопка «Скопировать», кнопка «Перевыпустить токен»
  (старый перестаёт работать), счётчик полученных отзывов по проекту, дата последней отправки (ставится при «Скопировать»).
- Токены хранить там же (`scripts/review-tokens.json`), изменение — через API админки (`adminRouter`), с бэкапом файла перед записью.

## 2. Открытая форма «Оставить отзыв»
- Страница `/{lang}/review` (без токена) + кнопка «Оставить отзыв» в блоке отзывов (и в футере ссылкой).
- Поля: имя, компания/роль (необяз.), проект (выпадающий список из portfolio.json + «Другое»), оценка 1–5, текст ≥ 20 символов,
  email для связи (не публикуется), 2 согласия (публикация + обработка ПДн 152-ФЗ/DSGVO).
- Сохраняется с `verified: false`, `source: "open"`; на сайте — без бейджа «Проверенный клиент».
- Антиспам: honeypot-поле, rate-limit (3 в сутки с IP), минимальное время заполнения 5 с, отказ при ссылках в тексте > 1.
- Telegram-уведомление помечает «открытая форма» vs «по личной ссылке».

## 3. Автоматическая просьба об отзыве
- В платформе: когда проект клиента в кабинете переходит в статус «Запуск» (launch) или «Поддержка» — через 7 дней письмо клиенту
  (ru/de/en по языку аккаунта) с личной ссылкой его проекта; если проекта нет в portfolio.json — токен создаётся автоматически.
- Одно письмо на проект; повтор — не раньше 30 дней и только если отзыва нет; отписка — ссылкой в письме.
- В карточке проекта в админке: «Просьба об отзыве отправлена <дата>» / «Отзыв получен».
- Пока SMTP не настроен — задание ставится в очередь и уходит Telegram-напоминание Pavel «пора попросить отзыв у <клиент>» с готовой ссылкой.

## 4. Импорт отзывов с площадок (основа, без парсинга чужих сайтов)
- Модель отзыва + поле `source`: `site` | `open` | `kwork` | `flru` | `habr` | `google` | `yandex` | `other`, `sourceUrl`.
- Админка → «Добавить отзыв с площадки»: Pavel вставляет текст, имя, оценку, дату и ссылку на оригинал → сразу `approved`, `verified: false`.
- На сайте у таких отзывов подпись «Отзыв с Kwork / FL.ru / Google …» со ссылкой на оригинал (rel="nofollow noopener").
- Google Business / Яндекс Бизнес API — только заготовка (флаги, пустые ключи в .env), без автоматического сбора.

## 5. Вывод на сайте
- Блок отзывов: сортировка — проверенные сначала, затем по дате; на странице кейса — отзывы этого проекта.
- JSON-LD Review / AggregateRating — только при ≥ 3 одобренных и только по отзывам с сайта (не с площадок — у них свой рейтинг).
- Пока одобренных 0 — показывается блок «С кем работаю» из 09 + кнопка «Оставить отзыв».

## 6. Проверки и отчёт
Отправка отзыва по ссылке и через открытую форму доходит до модерации и Telegram; approve → появляется на главной и в кейсе без пересборки;
reject → не виден; антиспам срабатывает; письмо/напоминание об отзыве ставится в очередь по смене статуса проекта.
