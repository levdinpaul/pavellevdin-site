## 1. Меню шапки = страницы футера + вход
Сейчас в шапке 4 ссылки (Обо мне, Портфолио, Услуги, Контакты), в футере больше: Блог, Бриф, Калькулятор, Визитка, Кабинет.
- Desktop: Обо мне · Портфолио · Услуги · Блог · Калькулятор · Контакты, затем «Ещё ▾» (Бриф, Визитка) — выпадашка
  доступная с клавиатуры (Esc закрывает, фокус-ловушка не нужна, aria-expanded/aria-controls), затем языки, затем **«Войти»**,
  затем CTA «Запустить проект». Если не помещается на 1280 — «Калькулятор» тоже в «Ещё». Проверить 1280 / 1366 / 1440 / 1920.
- Mobile-меню: ВСЕ пункты футера + «Войти/Кабинет» отдельной кнопкой вверху меню + языки + CTA.
- ⌘K-палитра: те же пункты + «Войти».
- Блог, Кабинет, Вход — платформа: обычный `<a href>` (список в lib/platform-paths.ts), не Link.
- **«Войти» ↔ «Кабинет»**: если пользователь вошёл — в шапке «Кабинет» (иконка-человек + текст), иначе «Войти» → /{lang}/login.
  Как узнать: платформа при входе ставит НЕ-httpOnly cookie-флаг `pl_auth=1` (Path=/, SameSite=Lax, без данных), при выходе удаляет;
  сайт читает только флаг. JWT остаётся httpOnly. Добавить в pl-platform (вход по паролю, magic-link, VK, выход). SSR-разметка — «Войти»,
  после гидрации переключается без сдвига (одинаковая ширина/скелетон, CLS 0).
- i18n ru/de/en для новых ключей.

## 2. Полная валидация сайта и платформы (все локали)
Собрать список URL: sitemap.xml + все маршруты ru/de/en + платформа (login, register, forgot/reset, blog, статьи, 404).
Проверить и ИСПРАВИТЬ всё найденное (что нельзя исправить без решения Pavel — в отчёт):
1. HTML: W3C Nu Validator (vnu-jar через npx или docker) по prerender-HTML каждой страницы — 0 ошибок (предупреждения — в отчёт).
2. Ссылки: linkinator/broken-link-checker по всему сайту, включая внешние (портфолио, соцсети) — 0 битых; mailto/tel корректны.
3. Доступность: axe-core (playwright) на каждом шаблоне — 0 serious/critical; контраст, alt, порядок заголовков (один h1), label у полей,
   focus-visible, skip-link, aria у меню/выпадашки, landmark-и (один main — убрать вложенные <main> на contact/brief/business-card/imprint/статье).
4. SEO: уникальные title/description, canonical, hreflang взаимные (ru/de/en/x-default), og/twitter-теги и og-картинка 1200×630,
   robots.txt, sitemap — все URL 200 и без noindex; две <title> на странице (известный баг) — убрать.
5. Структурированные данные: JSON-LD каждого шаблона через schema.org validator (validator.schema.org) / Google Rich Results — 0 ошибок.
6. Безопасность/заголовки (nginx russh + платформа): HTTPS-редиректы, HSTS, X-Content-Type-Options, Referrer-Policy, Permissions-Policy,

7. Производительность: PageSpeed (pagespeed.web.dev) главной, кейса, услуг, блога — mobile ≥ 85, desktop ≥ 95; ошибки консоли — 0.
8. Формы: лид, бриф, калькулятор, отзыв, регистрация/вход — валидация полей, понятные ошибки, согласие 152-ФЗ, успешная отправка.
9. i18n: нет пустых/отсутствующих ключей и русских строк в de/en (и наоборот).
10. Мобильные: 375 / 390 / 768 — без горизонтального скролла и наложений.
